# MPI 介绍 + ANN 选题要求提取

## 一、多进程与多线程介绍

### 进程 vs 线程

- **进程 (process)**：操作系统进行**资源分配**的最小单元
- **线程 (thread)**：操作系统进行**运算调度**的最小单元
- 一个进程可以包含多个线程，但每个线程只能属于一个进程
- 每个进程有**独立的地址空间**；同一进程内不同线程共享内存
- 不同进程**不共享地址空间**，必须通过特定函数(通信)交换数据
- **OpenMP 和 Pthread 均为多线程编程；MPI 是多进程编程**

### MPI 多进程关键点

- 通过 `mpiexec -n num ./test` 启动 `num` 个进程
- `MPI_Init` 与 `MPI_Finalize` **不等同于** "线程创建/销毁"：
    - 程序**整体并行执行**，不是只在二者之间并行
    - 二者之间负责完成数据划分、运算、通信等工作
- 验证示例：在 `MPI_Init` 之前的 `cout<<"Hello world!"` 也会被每个进程各打印一次，共 `num` 次

### MPI C++ 编程要素

**头文件**

```cpp
#include "mpi.h"
```

**预定义数据类型**：`MPI_CHAR`, `MPI_SHORT`, `MPI_INT`, `MPI_LONG`, `MPI_UNSIGNED_CHAR`, `MPI_FLOAT`, `MPI_DOUBLE` …

**常用 MPI 函数**

| 函数 | 作用 |
| --- | --- |
| `MPI_Init(&argc, &argv)` | 初始化 MPI |
| `MPI_Finalize()` | 清理并结束 MPI |
| `MPI_Comm_size(comm, *size)` | 获取总进程数 |
| `MPI_Comm_rank(comm, *rank)` | 获取当前进程编号 (0 ~ size-1) |
| `MPI_Send(buf, count, datatype, dest, tag, comm)` | 阻塞发送 |
| `MPI_Recv(buf, count, datatype, source, tag, comm, *status)` | 阻塞接收 |

### 4.1 IVF（共 9 分）

**基础迁移（3 分）**

- 实现思路与多线程基本一致，可在已有的 **IVF-SIMD** 或 **IVF-PQ-SIMD** 实现上迁移
- 流程：
    1. 将 **base data** 划分到不同 MPI 进程
    2. 每个进程维护自己的一部分 **inverted list**
    3. 查询到来时**广播**到所有 MPI 进程
    4. 每个进程**本地搜索**并维护**局部 top-p**
    5. 由一个进程做 **top-k 的 merge / reduce**

**混合并行（4 分）**

- 与 **Pthread / OpenMP** 结合，例如：
    - 进程间 MPI 并行
    - 进程内 query 级并行、簇级并行、rerank 阶段并行
- 注意点：
    - 进程数、线程数**并非越多越好**（启动 + 通信开销）
    - 注意进程/线程的**负载均衡**
    - 报告中体现思考

**进一步优化分析（2 分）**

- 负载均衡、merge/reduce、通信优化等深入分析

### 4.2 图索引（共 6 分）

**方案 A：IVF + HNSW（2 分）**

- 先对数据集构建 IVF 索引
- 在每个 IVF 簇中建立 HNSW
- 搜索时簇之间用 MPI 并行
- 若实现了 HNSW 查询内并行，可在簇内再用多线程加速 HNSW 搜索

**方案 B：分块 HNSW（2 分）**

- 将数据集划分为 P 个部分（P = 2~8；可随机划分或启发式划分）
- 对每个部分单独建立 HNSW
- MPI 在多个 HNSW 间并行搜索
- 最后做 top-k merge

**方案 C：其它组合策略（2 分）**

- 可自由探索其他 IVF 与 HNSW 组合，例如指导书提到的 **HNSW-on-HNSW**
- 核心思想：对数据集做某种划分，然后在不同划分间并行搜索

> ⚠️ 若上述并行方法出现**负优化**，只需在报告中如实汇报实验结果并给出合理分析即可。
