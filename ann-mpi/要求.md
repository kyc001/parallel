# MPI 介绍 + ANN 选题要求提取

## 一、多进程与多线程介绍

### 进程 vs 线程

- **进程 (process)**：操作系统进行**资源分配**的最小单元
- **线程 (thread)**：操作系统进行**运算调度**的最小单元
- 一个进程可以包含多个线程，但每个线程只能属于一个进程
- 每个进程有**独立的地址空间**；同一进程内不同线程共享内存
- 不同进程**不共享地址空间**，必须通过特定函数(通信)交换数据
- **OpenMP 和 Pthread 均为多线程编程；MPI 是多进程编程**

### MPI 多进程关键点

- 通过 `mpiexec -n num ./test` 启动 `num` 个进程
- `MPI_Init` 与 `MPI_Finalize` **不等同于** "线程创建/销毁"：
    - 程序**整体并行执行**，不是只在二者之间并行
    - 二者之间负责完成数据划分、运算、通信等工作
- 验证示例：在 `MPI_Init` 之前的 `cout<<"Hello world!"` 也会被每个进程各打印一次，共 `num` 次

### MPI C++ 编程要素

**头文件**

```cpp
#include "mpi.h"
```

**预定义数据类型**：`MPI_CHAR`, `MPI_SHORT`, `MPI_INT`, `MPI_LONG`, `MPI_UNSIGNED_CHAR`, `MPI_FLOAT`, `MPI_DOUBLE` …

**常用 MPI 函数**

| 函数 | 作用 |
| --- | --- |
| `MPI_Init(&argc, &argv)` | 初始化 MPI |
| `MPI_Finalize()` | 清理并结束 MPI |
| `MPI_Comm_size(comm, *size)` | 获取总进程数 |
| `MPI_Comm_rank(comm, *rank)` | 获取当前进程编号 (0 ~ size-1) |
| `MPI_Send(buf, count, datatype, dest, tag, comm)` | 阻塞发送 |
| `MPI_Recv(buf, count, datatype, source, tag, comm, *status)` | 阻塞接收 |

## 一、 MPI 多进程概念介绍

这份指导书对 MPI 编程的基础概念以及它与多线程的对比进行了清晰的讲解：

* **进程与线程的区别**：
* 
**进程（Process）**是操作系统进行**资源分配**的最小单元 ；而**线程（Thread）**是操作系统进行**运算调度**的最小单元 。


* 
**内存共享机制**：每个进程都有**独立**的地址空间 。在同一个进程内的不同线程可以共享该进程的内存，但**不同进程之间是不共享地址空间的** 。如果一个进程需要访问另一个进程的数据，必须通过特定的函数进行通信 。




* **MPI 运行与执行机制**：
* 
**整体并行**：通过命令（如 `mpiexec -n num ./test`）运行 MPI 程序时，系统会直接创建 `num` 个进程来同时运行该程序 。


* 
**非局部并行**：代码中调用的 `MPI_Init`（初始化）和 `MPI_Finalize`（清理）与多线程的创建/销毁不同 。**程序并非只在这两个函数之间并行，而是整体代码都在并行执行** 。这两个函数之间主要负责的是数据划分、运算和通信等核心工作 。




* **常用预定义类型与函数**：
* 
**数据类型**：支持 `MPI_CHAR`、`MPI_INT`、`MPI_FLOAT`、`MPI_DOUBLE` 等 。


* 
**核心核心函数**：包括用于报告进程总数的 `MPI_Comm_size` 、获取当前进程号（Rank，范围 $0$ 到 $size-1$）的 `MPI_Comm_rank` 、以及进行点对点阻塞式数据收发的 `MPI_Send` 和 `MPI_Recv` 。

## 二、 ANN（近似最近邻）选题要求

ANN 选题的基础要求得分最高为满分的 90%（对应最高分 13.5 分） 。该选题的重点在于**探索在多进程上的数据划分和并行搜索** 。

在撰写报告和实现代码时，需要重点关注以下几个维度 ：

> * MPI 进程划分方式与多进程间的**负载均衡** ；
> * `merge`/`reduce` 的开销 ；
> * MPI 与 SIMD / 多线程的**混合并行** ；
> * **通信与计算的重叠**（Overlap） ；
> * 分布式 **Cache 局部性**（Locality）问题 ；
> * 始终需要关注的 **Recall-Latency Trade-off**（准确率与延迟的权衡） 。
> 
> 

具体选题细分为以下两个子方向：

### 1. IVF（倒排文件索引）实现要求（共 9 分）

* **基础迁移方法（3 分）**：
* 将基础数据（Base data）划分到不同的 MPI 进程中，每个进程各自维护一部分倒排列表（Inverted list） 。


* 当查询（Query）到来时，将其**广播**到所有 MPI 进程 。


* 每个进程在本地完成搜索并维护局部 Top-p，最后由一个主进程进行 Top-k 的 `merge`/`reduce` 。（可选择之前的 IVF-SIMD 或 IVF-PQ-SIMD 进行迁移 ）。




* **混合并行优化（4 分）**：
* 在基础 MPI 搜索之上，进一步结合 Pthread 或 OpenMP 进行混合并行 。


* 可以设计：**进程间 MPI 并行 + 进程内 Query 级并行/簇级并行/Rerank 阶段并行** 。


* 
*注意*：需要合理设置进程数和线程数（并非越多越好，要考虑启动和通信开销），并重点优化**负载均衡**，将思考体现在报告中 。




* **进一步优化与分析（2 分）**：
* 针对负载均衡、`merge`/`reduce` 以及通信方面进行更深层次的优化与分析 。





### 2. 图索引（HNSW）实现要求（共 6 分）

指导书提供了三种可以自由讨论和探索的组合策略（每种策略对应 2 分）：

* 
**策略一（IVF + HNSW）**：先对数据集构建 IVF 索引，在 IVF 的每个簇（Cluster）内部建立 HNSW 索引 。搜索时，**簇之间使用 MPI 进行并行搜索** 。如果实现了 HNSW 的查询内并行，可在簇内利用多线程进一步加速 。


* 
**策略二（数据集切分 + 独立 HNSW）**：直接将数据集划分为 $P$ 个部分（$P$ 可设为 $2 \sim 8$，采用随机划分或启发式策略） 。每个部分独立建立 HNSW，搜索时**利用 MPI 在不同的 HNSW 之间进行并行搜索**，最后进行 Top-k 的 `merge` 。


* 
**策略三（其他组合/HNSW-on-HNSW）**：自由讨论其他 IVF 和 HNSW 的组合策略（如 HNSW-on-HNSW） 。核心思想都是对数据集进行某种划分，然后在不同的划分间开展并行搜索 。
