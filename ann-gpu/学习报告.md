## 一、贯穿全程的 GPU 加速心法

在动手改每个 Lab 之前,先把六个 Lab 共同的“加速六条”抽出来:

| 原则 | 含义 | 出现的 Lab |
| --- | --- | --- |
| 合并访存 (coalescing) | 相邻线程读相邻地址,把多次访存合成一个 cache line | 全部 |
| 共享内存 (LDS) | 片上高速内存做复用 / 中转,避免重复走全局 | Lab2/3/4/5/6 |
| 减少原子争用 | 两级归约:先 block 内聚合,再少量全局原子 | Lab3/4/5/6 |
| 每线程多元素 + grid-stride | 提高算术强度,解耦线程数与数据量 | Lab3/4/5 |
| warp 级原语 (shuffle) | warp 内 lockstep,免 __syncthreads 做归约 | Lab4(进阶) |
| 启动配置 / occupancy | 合理 block 大小,用 occupancy API 调参 | Lab1/3 |

## 二、逐 Lab 加速拆解

### Lab 1 · Vector Addition — 入门:线程索引与带宽

**它怎么加速的**:最基础的 SIMT 模型——每个线程算一个元素 `c[i]=a[i]+b[i]`,`i = blockIdx.x*blockDim.x + threadIdx.x`。成千上万线程同时跑,连续线程读连续地址 → 完美合并访存。

**本质**:这是个 **纯带宽受限**问题。每个元素 2 读 1 写、只做 1 次加法,算术强度极低,性能上限就是显存带宽。

**我的更快思路**:

- 用 **向量化譻入 `float4`/`double2`**:一条指令搬 128 bit,减少指令数与内存事务数,更接近带宽峰值。
- 用 **grid-stride loop** 让固定数量的 block 处理任意大 N,减少 launch 开销、提高复用。

### Lab 2 · Matrix Transpose — 共享内存 + bank conflict

**它怎么加速的**:转置的难点是“读合并但写不合并”(或反之)。用 **tile 分块 + 共享内存中转**:整块合并读进 LDS,再从 LDS 按转置后的顺序合并写回全局。关键细节是 `tile[BLOCK_SIZE][BLOCK_SIZE+1]` 的 **+1 padding**——错开 bank 映射,避免同一列访问全部落在同一 bank 造成 bank conflict。

**本质**:用片上内存把“不合并”转换成“合并 + 一次 LDS 重排”。

**我的更快思路**:

- 除了 +1 padding,还可试 **对角块重排(diagonal block reordering)** 减轻 partition camping。
- 每线程搬多行(“thread coarsening”),提高每个 block 的有效吞吐。

### Lab 3 · Histogram — 两级原子归约

**它怎么加速的**:直方图的痛点是原子争用。用**两级直方图**:每 block 先在 LDS 建 `sdata[1024]` 的局部直方图(block 内原子,快),`__syncthreads()` 后再把局部结果一次性 merge 到全局。配合 grid-stride 和 `hipOccupancyMaxPotentialBlockSize` 调最优 block 大小。

**本质**:把“每个输入一次全局原子”压成“每 block × bins 次全局原子”。

**我的更快思路**:

- bins 少时做 **per-warp 多份副本(privatization)**,进一步减少 LDS 原子争用。
- 用 **warp 聚合(match/ballot)** 先在 warp 内把同一 bin 的增量加起来,减少原子调用次数。

### Lab 4 · Reduction — 树形归约 / warp shuffle

**它怎么加速的**:共享内存树形归约,每步减半活跃线程(`for s=blockDim/2; s>0; s>>=1`),配 `__syncthreads()`。进阶点:多元素/线程、warp shuffle。

**本质**:把 O(N) 串行求和变成 O(log N) 深度的并行树。

**关键认识**(来自 Lab4 习题):

- block=64 、N=1M → 15625 次全局原子;block=1024 → 仅 977 次。**block 越大 → 全局原子越少 → 越快**。
- 首步后 50% 线程立即闲置——这正是该用 warp shuffle / 多元素的动机。
- warp shuffle 不需 `__syncthreads()`(warp 内 SIMD lockstep)。

**我的更快思路**:warp-shuffle 归约 + grid-stride + 每线程多元素,全程只在跨 warp 时用一次 LDS,block 末只一次全局原子。**代码见第四节。**

### Lab 5 · Monte Carlo — “尴尬并行 + 归约”

**它怎么加速的**:两阶段——每点独立算 `(b-a)·y/n`(完全并行),再求和(归约)。naive 版用全局 `atomicAdd` 汇总,是 O(N) 串行瓶颈;优化版（Section 9）用共享内存树归约 + grid-stride,每 block 只 1 次全局原子。

**关键认识**:

- naive 原子版有效率 ≈ 1/(1+100) = **1%**(计算 1 周期 vs 原子 100 周期)。
- N=1M、256 block → 优化版只需 **256** 次全局原子。
- 数值:double ≈ 15–17 位有效数字;float 仅 7 位,N=100M 会出现“small 被 swamping 吞掉”。

**我的更快 / 更准思路**:把 MC 直接套进 warp-shuffle 归约;精度上用 **Kahan 补偿求和** 减小累加误差。

### Lab 6 · K-Means(Capstone)— 多 kernel 编排

**它怎么加速的**:三个 kernel——分配(每点一线程找最近质心,O(N·k))、更新(共享内存两级原子归约累加坐标与计数)、finalize(求均值 + GPU 端收敛检测)。加上 **双缓冲 ping-pong** 避免读写冲突与拷贝。

**关键认识**:质心是“只读 + 广播”,被每个线程反复读——这是最大优化点。主导计算是分配 kernel。

**我的更快思路**:把质心**预载入共享内存**,所有线程从 LDS 读,避免重复走全局/L2;更新阶段用 warp 级归约减少 LDS 原子;每线程处理多点。**代码见第四节。**

### 4.1 warp-shuffle 归约（适用 Lab4 / Lab5）

比“共享内存树归约”更快的原因:**warp 内用寄存器 shuffle 交换,零 LDS、零 `__syncthreads`**;只在跨 warp 时用一点 LDS;每 block 仅 1 次全局原子;再加 grid-stride 每线程吃多个元素。

```bash
cd /opt/workspace/HIP/Lab4_Reduction   # 或 Lab5
cat > reduce_fast.hip <<'EOF'
#include <hip/hip_runtime.h>
#include <iostream>
#include <vector>

// warp 内归约:用寄存器 shuffle,无需 __syncthreads
__inline__ __device__ double warpReduceSum(double val) {
    for (int offset = warpSize / 2; offset > 0; offset >>= 1)
        val += __shfl_down(val, offset);
    return val;
}

__global__ void reduce_fast(const double* in, double* out, int n) {
    // 1) grid-stride:每线程累加多个元素
    double sum = 0.0;
    for (int i = blockIdx.x * blockDim.x + threadIdx.x;
         i < n; i += blockDim.x * gridDim.x)
        sum += in[i];

    // 2) warp 内归约(零 LDS / 零同步)
    sum = warpReduceSum(sum);

    // 3) 每 warp 一个部分和 → LDS
    __shared__ double shared[64];        // 足够容纳 wave32/wave64
    int lane = threadIdx.x % warpSize;
    int wid  = threadIdx.x / warpSize;
    if (lane == 0) shared[wid] = sum;
    __syncthreads();

    // 4) 第一个 warp 把各 warp 的部分和再归约,每 block 只 1 次全局原子
    int numWarps = (blockDim.x + warpSize - 1) / warpSize;
    sum = (threadIdx.x < numWarps) ? shared[lane] : 0.0;
    if (wid == 0) {
        sum = warpReduceSum(sum);
        if (lane == 0) atomicAdd(out, sum);
    }
}

int main() {
    int n; std::cin >> n;
    std::vector<double> h(n);
    for (int i = 0; i < n; ++i) std::cin >> h[i];

    double *d_in, *d_out;
    hipMalloc(&d_in,  n * sizeof(double));
    hipMalloc(&d_out, sizeof(double));
    hipMemcpy(d_in, h.data(), n * sizeof(double), hipMemcpyHostToDevice);
    hipMemset(d_out, 0, sizeof(double));

    int tpb = 256;
    int blocks = (n + tpb - 1) / tpb;
    if (blocks > 1024) blocks = 1024;   // grid-stride 下用固定上限即可
    reduce_fast<<<blocks, tpb>>>(d_in, d_out, n);
    hipDeviceSynchronize();

    double result;
    hipMemcpy(&result, d_out, sizeof(double), hipMemcpyDeviceToHost);
    std::cout << result << std::endl;
    hipFree(d_in); hipFree(d_out);
}
EOF
hipcc -O3 -Wno-unused-value reduce_fast.hip -o reduce_fast
echo "5 1 2 3 4 5" | ./reduce_fast   # → 15
```

### 4.2 K-Means 分配 kernel:质心进共享内存（适用 Lab6）

原版每个线程都从全局重复读 k 个质心。把质心**协作预载入 LDS**,同 block 内所有线程从片上读,大幅减少全局/L2 流量(质心是广播访问,收益明显)。

```cpp
// 替换 Lab6 的 find_nearest_centroids_kernel(启动时传入 2*k*sizeof(float) 共享内存)
__global__ void find_nearest_cached(
        const float* data_x, const float* data_y, int* labels,
        const float* cx, const float* cy, int sample_size, int k) {
    extern __shared__ float s[];
    float* scx = s;          // 前 k 个:质心 x
    float* scy = s + k;      // 后 k 个:质心 y
    for (int j = threadIdx.x; j < k; j += blockDim.x) {
        scx[j] = cx[j];
        scy[j] = cy[j];
    }
    __syncthreads();

    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < sample_size) {
        float px = data_x[i], py = data_y[i];   // 只读一次到寄存器
        int best = 0; float bd = INFINITY;
        for (int j = 0; j < k; ++j) {
            float dx = scx[j] - px, dy = scy[j] - py;
            float d = dx * dx + dy * dy;
            if (d < bd) { bd = d; best = j; }
        }
        labels[i] = best;
    }
}
// 启动:find_nearest_cached<<<blocks, tpb, 2*k*sizeof(float)>>>(...);
// 注:需 2*k*sizeof(float) ≤ LDS 容量(本平台 k ≤ 100 完全够用)。
```

## 五、总结:我学到的

1. **先判断瓶颈再优化**:向量加/转置是带宽受限,加法/归约/直方图是原子争用受限——不同瓶颈对应不同手段。
2. **共享内存是万能中转站**:转置重排、直方图/归约聚合、K-Means 质心缓存,本质都是“用片上内存减少慢的全局访问”。
3. **原子要“分层”**:block 内先聚合 → 每 block 少量全局原子。block 越大、原子越少。
4. **warp 是免费的同步域**:shuffle 归约无需 `__syncthreads`,比 LDS 树归约更快。
5. **每线程多干活(coarsening) + grid-stride**:提高算术强度、减少 block/原子数、解耦线程与数据量。
6. **移植性细节**:RDNA 上用 `warpSize`、注意 wave32/wave64;FP32 与 FP64 的精度权衡(swamping / Kahan)。
7. **多 kernel 编排 + GPU 端收敛检测**:K-Means 把迭代算法拆成多个 kernel,用双缓冲避免读写冲突——这是真实 GPU 应用的缩影。
