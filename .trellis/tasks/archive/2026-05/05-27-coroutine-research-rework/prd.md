# 协程技术调研深度重构

## 背景

kyc001 正在完成"并行程序设计"课程的协程技术调研作业。要求提交 15 分钟 Slides + 可选 PDF 报告。截止日期：2026 年 6 月 12 日（课堂报告）。

## 当前状态

### 现有产出
- `report.tex` / `report.pdf` — LaTeX 调研报告（~323 行）
- `slides.typ` / `slides.pdf` — Typst 幻灯片（~596 行，23 页）
- `main.tex` / `main.pdf` — LaTeX Beamer 幻灯片（与 slides.typ 内容基本一致）
- `bench.py` / `bench.go` / `Bench.java` — 三语言基准测试代码
- `plot_results.py` — matplotlib 图表生成
- `fig/` — 4 张实验图表
- `results/` — 实验原始数据
- `references.bib` — 12 条参考文献

### 已识别的四个问题

1. **内容深度不够**
   - report.tex 仅 323 行，技术分析浅
   - 缺少深入的底层实现分析
   - references.bib 只有 12 条，缺少关键论文
   - 选型建议过于泛化

2. **结构/逻辑混乱**
   - report.tex 和 slides.typ 的章节组织有差异，叙事线不一致
   - slides 有 23 页但内容密度不均匀
   - report 缺少"相关工作"和"局限性"等学术报告常见章节

3. **实验部分薄弱**
   - 每个测试只跑一次，无重复测量和统计分析
   - 内存对比只覆盖 Python
   - 切换微基准跨语言不等价
   - 缺少 warm-up、环境隔离等实验规范

4. **排版/美观问题**
   - 图表只有 4 张基础柱状图
   - 缺少架构图、流程图、时序图等技术示意图
   - 排版可以更精细

## 目标

对 Slides 和报告进行深度重构。

## 已确认决策

1. **砍掉 `main.tex`（beamer）**，集中精力做 `slides.typ` + `report.tex`
2. **精力分配**：Slides 60%，Report 40%
3. **叙事线重构为 5 模块**：为什么需要协程 → 协程是什么 → 语言怎么支持 → 实验验证 → 总结与选型（15-19 页）
4. **语言对比改为按机制分组**（有栈 vs 无栈），不再逐语言罗列
5. **实验改进**：重复 5 次测量 + mean±std；补全 Go/Java 内存采样；切换微基准不等价性用文字说明
6. **图表改进**：补充技术示意图（并发演进、状态机编译、GMP 调度、三层协同）；柱状图加误差线

## 验收标准

- [ ] slides.typ 重构为 5 模块、15-19 页，叙事线清晰
- [ ] report.tex 内容深度提升，结构与 slides 一致
- [ ] 实验每个测试跑 5 次，报告 mean ± std
- [ ] Go/Java 补充内存采样
- [ ] 4 张技术示意图嵌入 slides
- [ ] 柱状图加误差线
- [ ] 参考文献补充至 20+ 条
- [ ] 删除 main.tex 相关文件
- [ ] 所有图表重新生成
- [ ] slides.pdf 和 report.pdf 编译通过
