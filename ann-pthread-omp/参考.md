## 三、ANN 具体实现方向

### 1. Flat-SIMD + 多线程并行

在 SIMD 实验中的 Flat-SIMD 基础上，进一步使用 Pthread / OpenMP 做并行优化。

可考虑的并行方式包括：

- query 级并行；
- base 向量划分并行；
- top-k reduce。

注意事项：

- 如果采用 base 向量划分，每个线程维护的 `top-p` 中 `p` 的取值会影响 recall 与 latency 的 trade-off；
- 可尝试通过调整 schedule 策略改善负载均衡。

---

### 2. PQ-SIMD + 多线程优化

PQ-SIMD 分为两个阶段：

#### 2.1 PQ 编码阶段

包括：

- KMeans / KMeans++ 聚类；
- 向量编码。

要求与说明：

- 如果 SIMD 实验中已实现相关优化，可继续做多线程优化；
- 该部分不是性能考核重点；
- 高质量并行优化可作为进阶加分。

#### 2.2 查询阶段

默认查询方式为 ADC。

查询阶段包括：

##### 2.2.1 LUT 构建阶段

LUT 构建本质上是 dense compute。

可考虑的并行方式包括：

- 子空间并行；
- 子查询向量并行；
- 类中心集合并行。

说明：

- 如果 SIMD 实验中实现了跨 centroid 并行，可进一步结合 Pthread / OpenMP；
- 该阶段计算较规则，通常能获得较稳定的并行加速。

##### 2.2.2 查表累加阶段

该阶段从“计算距离”转为“查表 + 累加”。

需要关注：

- PQ code 对 LUT 的访问通常随机；
- cache miss 与内存带宽可能成为主要限制；
- 瓶颈可能从 compute-bound 转向 memory-bound。

推荐探索：

- batch query 并行；
- 单 query 下对 base 向量集合分块并行扫描；
- 每个线程维护局部 top-p，最后 merge；
- SIMD 中已实现的 gather、shuffle、FastScan、批量 gather 等方法与多线程结合后的性能。

注意事项：

- 线程数不一定越多越好；
- 可能出现负优化；
- 需要在报告中分析负优化原因。

---

## 四、IVF 方向要求

### 1. IVF 索引构建

要求：

- 使用聚类算法对 base data 聚类；
- 保存每个簇的质心；
- 保存每个簇中点的编号集合；
- 簇数通常根据 base data 大小设置，一般为 64 到 4096；
- 可对内存进行重排，将同簇向量连续存储，以降低查询时 cache miss。

说明：

- 索引构建性能不是重点；
- 可仿照 PQ 编码阶段探索 SIMD 与多线程优化。

---

### 2. IVF 查询过程

IVF 查询包括两个阶段：

#### 2.1 粗排阶段

要求：

- 计算 query 到每个簇中心的距离；
- 排序后选出最近的前 `nprobe` 个簇。

需要分析：

- `nprobe` 越大，准确率通常越高，但延迟也越高；
- 实验结果中需要调整 `nprobe`；
- 需要绘制 recall-latency 曲线。

#### 2.2 精排阶段

要求：

- 对选出的 `nprobe` 个簇中的点使用原始精度进行精确查询 / rerank。

---

### 3. IVF-SIMD baseline 及其多线程优化

#### 3.1 IVF-SIMD baseline

需要实现：

- 使用 IVF 减少搜索点数量；
- 使用 SIMD 优化单次距离计算。

#### 3.2 多线程优化

在 IVF-SIMD baseline 基础上进一步探索 Pthread / OpenMP 多线程优化。

##### 粗排阶段

可尝试：

- query 级并行；
- 簇中心并行。

注意事项：

- 粗排阶段计算量通常较小；
- 多线程可能因线程创建、同步、reduce 开销导致负优化；
- 需要分析线程数与性能之间的关系。

##### 精排阶段

可探索：

- 簇划分并行；
- query 级并行。

注意事项：

- 精排阶段通常是 IVF 查询的主要开销，更适合多线程优化；
- inverted list 长度通常不均匀；
- 线程划分方式、schedule 策略会显著影响性能；
- 涉及 top-k reduce 时，需要分析每个线程的 top-p 设置对 recall 与 latency 的影响。

---

### 4. IVF-PQ-SIMD baseline 及其多线程优化

#### 4.1 实现方式

可将 IVF 与 PQ 结合，常见方法包括：

1. 先对所有 base data 做 PQ，再构建 IVF 索引；
2. 先构建 IVF 索引，再在每个簇中分别做 PQ。

#### 4.2 分析要求

需要分析两种方法在以下方面的差异：

- 准确性；
- 性能。

#### 4.3 多线程优化要求

需要关注：

- IVF-PQ 中，PQ 会显著降低单次距离计算量；
- 系统瓶颈可能进一步从 compute-bound 转向 memory-bound；
- 多线程优化时，线程数不一定越多越快；
- 可能出现负优化；
- 需要结合 latency、recall、具体实现和线程数综合分析系统性能。
