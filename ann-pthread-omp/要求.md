- 内容类似高斯消去基础要求，需要完成：
  - 基础 Pthread 并行化实现；
  - 基础 OpenMP 并行化实现；
  - 与 SIMD 优化结合；
  - 性能测试；
  - 串行与并行对比；
  - 不同线程数、不同问题规模下的实验分析；
  - 算法策略、任务划分、调度策略、负载均衡、cache/内存访问等优化讨论；
  - Pthread 与 OpenMP 的性能差异分析；
  - 撰写研究报告，要求类似 SIMD 编程作业，篇幅不超过 25 页。
- 分数上限高于高斯消去不代表实际得分一定更高，最终根据完成情况、实验质量、性能分析深度和报告质量综合评定。

## 2. OpenMP 要求
- ANN 的 OpenMP 实现思路与 Pthread 基本相同。
- 算法细节参考 Pthread 实验指导书。
- OpenMP 程序需使用 `-fopenmp` 编译。
- 可将 Pthread 实验改写为 OpenMP，并对比：
  - 任务划分方式；
  - SIMD 结合方式；
  - 运行时间；
  - 加速比；
  - 伸缩性；
  - profiling 结果；
  - OpenMP 与 Pthread 的性能差异。

## 3. ANN 具体基础/进阶实现方向

### 3.1 Flat-SIMD + 多线程并行（2 分）
- 在 SIMD 实验中的 Flat-SIMD 基础上，进一步使用 Pthread/OpenMP 做并行优化。
- 可考虑：
  - query 级并行；
  - base 向量划分并行；
  - top-k reduce。
- 若采用 base 向量划分，需要注意每个线程维护的 `top-p` 中 `p` 的取值会影响 recall 与 latency 的 trade-off。
- 可尝试通过调整 schedule 策略改善负载均衡。

### 3.2 PQ-SIMD + 多线程优化（2 分）
PQ-SIMD 分为两个阶段：

#### 阶段一：PQ 编码阶段
- 包括 KMeans/KMeans++ 聚类与向量编码。
- 如果 SIMD 实验中已实现相关优化，可继续做多线程优化。
- 该部分不是性能考核重点，但高质量并行优化可作为进阶加分。

#### 阶段二：查询阶段（默认 ADC）
查询阶段分为：

##### LUT 构建阶段
- 本质上是 dense compute。
- 可考虑：
  - 子空间并行；
  - 子查询向量并行；
  - 类中心集合并行。
- 如果 SIMD 实验中实现了跨 centroid 并行，可进一步结合 Pthread/OpenMP。
- 该阶段计算较规则，通常能获得较稳定的并行加速。

##### 查表累加阶段
- 从“计算距离”转为“查表 + 累加”。
- 瓶颈可能从 compute-bound 转向 memory-bound。
- PQ code 对 LUT 的访问通常随机，cache miss 与内存带宽可能成为主要限制。
- 推荐探索：
  - batch query 并行；
  - 单 query 下对 base 向量集合分块并行扫描；
  - 每个线程维护局部 top-p，最后 merge。
- 线程数不一定越多越好，可能出现负优化，需要在报告中分析。
- 如果 SIMD 中实现了 gather、shuffle、FastScan、批量 gather 等方法，可继续探索其与多线程结合后的性能。

## 4. IVF 方向

### 4.1 IVF 索引构建
- 使用聚类算法对 base data 聚类。
- 保存每个簇的质心和该簇中点的编号集合。
- 簇数通常根据 base data 大小设置，一般为 64 到 4096。
- 可对内存进行重排，将同簇向量连续存储，以降低查询时 cache miss。
- 索引构建性能不是重点，但可仿照 PQ 编码阶段探索 SIMD 与多线程优化。

### 4.2 IVF 查询过程
- 第一步：计算 query 到每个簇中心的距离，排序后选出最近的前 `nprobe` 个簇。
- `nprobe` 越大，准确率通常越高，但延迟也越高。
- 实验结果中需要调整 `nprobe`，绘制 recall-latency 曲线。
- 第二步：对选出的 `nprobe` 个簇中的点使用原始精度进行精确查询/rerank。

### 4.3 IVF-SIMD baseline（2 分）及其多线程优化（4 分）
- 先实现 IVF-SIMD baseline：
  - 使用 IVF 减少搜索点数量；
  - 使用 SIMD 优化单次距离计算。
- 在此基础上进一步探索 Pthread/OpenMP 多线程优化。

#### 粗排阶段
- 计算 query 到所有簇中心的距离，并选出前 `nprobe` 个簇。
- 计算量通常较小，多线程可能因线程创建、同步、reduce 开销导致负优化。
- 可尝试：
  - query 级并行；
  - 簇中心并行。
- 需要分析线程数与性能之间的关系。

#### 精排阶段
- 对选中簇进行扫描与距离计算。
- 通常是 IVF 查询的主要开销，更适合多线程优化。
- 可探索：
  - 簇划分并行；
  - query 级并行。
- 注意 inverted list 长度通常不均匀，线程划分方式、schedule 策略会显著影响性能。
- 涉及 top-k reduce 的方法，需要分析每个线程的 top-p 设置对 recall 与 latency 的影响。

### 4.4 IVF-PQ-SIMD baseline（3 分）及其多线程优化（5 分）
- 可将 IVF 与 PQ 结合，常见方法：
  1. 先对所有 base data 做 PQ，再构建 IVF 索引；
  2. 先构建 IVF 索引，再在每个簇中分别做 PQ。
- 需要分析两种方法在准确性和性能上的差异。
- IVF-PQ 中，PQ 会显著降低单次距离计算量，系统瓶颈可能进一步从 compute-bound 转向 memory-bound。
- 多线程优化时，线程数不一定越多越快，甚至可能负优化。
- 需要结合 latency、recall、具体实现和线程数综合分析系统性能。

## 5. HNSW 进阶要求（2 分）
- 可直接基于 hnswlib 开发，服务器框架中已提供索引构建示例。
- 可以只使用 HNSW 的底层图，并随机选择入口点。
- 可重点关注底层图搜索算法的并行化。
- 图索引上 query 内并行化较困难，但可以探索：
  - 边划分并行；
  - Layer 0 点划分并行；
  - 多入口点并行；
  - IVF + HNSW 嵌套结构：建立多个 HNSW，每个线程搜索一部分 HNSW。
- 上述优化可能导致负优化，如实汇报实验结果并给出分析即可。
